# Кадровые процессы МУИВ

Учебный проект по теме «Реинжиниринг процессов службы персонала для повышения качества кадрового состава».

Автор учебной работы: Бисенкулова Алина Владиславовна. Группа: о.ИЗДт 30.3/Б3-22.

Приложение демонстрирует маршрут от заявки на подбор до завершения адаптации. Оно не подключено к кадровым системам университета, не принимает реальные заявления о трудоустройстве и содержит вымышленные персональные записи.

## Что работает

- Десять публичных разделов с навигацией и хлебными крошками.
- Вход с тремя ролями: администратор, кадровый специалист, соискатель / новый сотрудник.
- Заявки на подбор с согласованием и публикация вакансий.
- Профиль соискателя и один отклик на выбранную вакансию.
- Воронка подбора с допустимыми переходами и контролем версии записи.
- Оценка компетенций от 0 до 5 с обязательным описанием наблюдаемого результата.
- Назначение, завершение и отмена собеседований.
- План адаптации, задания, сроки и подтверждение выполнения.
- Загрузка учебных PDF до 2 МБ и разграничение доступа к файлам.
- Формирование реестра откликов в XLSX и плана адаптации в DOCX.
- Поиск, уведомления, журнал действий, блокировка учебных пользователей.
- Пять отдельных административных страниц: пользователи, подразделения, роли, журнал и настройки.
- Массовая публикация черновиков в административном кабинете.

## Локальный запуск

Требуется Node.js 24 или новее. Встроенный SQLite доступен в этой версии Node.js; для запуска учебного режима дополнительные библиотеки не нужны.

```sh
node local-server.mjs
```

Откройте `http://localhost:3000`. На странице входа выберите учебную роль. Первый выбор создаёт начальный набор записей; последующие входы сохраняют сделанные изменения.

Параметры запуска:

```sh
node local-server.mjs --host 127.0.0.1 --port 3000
```

Локальная база и загруженные файлы сохраняются в `.sites-runtime/`. Этот каталог не включается в исходный код.

## PostgreSQL

В `local-db.js` предусмотрен отдельный адаптер PostgreSQL. Он использует параметризованные запросы и транзакции. SQL-схема находится в `schema.sql`; директива `PRAGMA` исключается при первичной инициализации PostgreSQL.

```sh
npm install
```

Создайте пустую базу PostgreSQL и передайте строку подключения через переменную окружения `DATABASE_URL`. После этого `node local-server.mjs` выберет PostgreSQL вместо SQLite. Строку подключения храните вне репозитория.

Автоматические проверки поставки выполнены на локальном SQLite. Адаптер PostgreSQL должен пройти отдельную приёмку в целевом окружении. Развёрнутый учебный стенд использует Cloudflare D1, совместимую с SQLite, и R2 для файлов.

## Структура исходного кода

| Файл | Назначение |
| --- | --- |
| worker.js | HTTP-маршрутизация и проверка закрытых страниц |
| api.js | Основные операции кадрового процесса |
| operations.js | Дополнительные операции вакансий, встреч и пользователей |
| security.js | Пароли, сессии, CSRF, валидация и заголовки |
| db.js | SQL-запросы, аудит и проверка владельца записи |
| schema.sql | Двадцать таблиц, связи и индексы |
| seed.js | Исключительно вымышленные учебные данные |
| client.js | Формы и поведение браузерного интерфейса |
| ui.js | HTML-каркас и навигация |
| public.js | Содержание десяти открытых разделов |
| styles.js | Адаптивное оформление |
| documents.js | Формирование настоящих файлов DOCX и XLSX |
| local-db.js | Адаптеры SQLite и PostgreSQL, локальное хранилище файлов |
| local-server.mjs | Запуск на Node.js |
| app.test.mjs | Проверки API, критического пути и разграничения доступа |
| build.mjs | Сборка самостоятельного модуля Worker |

## Проверка

```sh
node --test app.test.mjs
node build.mjs
```

Проверяются позитивные и негативные сценарии, полный критический путь подбора и адаптации, а также изоляция записей и защитные механизмы. Экспортированные файлы из автоматических проверок остаются в `.sites-runtime/exports/`.
