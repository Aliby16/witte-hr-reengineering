# Кадровые процессы МУИВ

Веб-сервис подбора, оценки компетенций и адаптации сотрудников по теме «Реинжиниринг процессов службы персонала для повышения качества кадрового состава».

Автор: Бисенкулова Алина Владиславовна. Группа: о.ИЗДт 30.3/Б3-22.

Сайт: https://br-small-resonance-bgwgooob-wittehrbisenkulova.compute.c-9.eu-central-1.aws.neon.tech/

## Возможности

Десять публичных страниц, три роли и 17 разделов личного кабинета. Соискатель заполняет профиль, отправляет отклик, просматривает встречи, план и документы. Специалист согласует заявки, публикует вакансии, ведёт оценки и адаптацию. Администратор управляет пользователями, подразделениями, ролями, журналом и настройками, массово публикует черновики.

Реестры поддерживают поиск, предметные фильтры, сортировку и страницы. Приложение проверяет владельца записи, допустимые переходы, версии оценок, конфликты встреч и сроки заданий. Доступны уведомления, управление сессиями, обратная связь, загрузка и обновление PDF до 2 МБ, выгрузки XLSX и DOCX.

Начальный набор содержит специально созданные тестовые записи.

## Установка и запуск

```sh
npm ci
npm start
```

Откройте http://localhost:3000. Без DATABASE_URL локальный запуск использует SQLite из состава Node.js. Выбор роли на странице входа создаёт начальный набор один раз и сохраняет последующие изменения.

```sh
npm start -- --host 127.0.0.1 --port 3000
```

Локальные данные и файлы находятся в .sites-runtime/.

## PostgreSQL и начальная миграция

1. Создайте пустую базу PostgreSQL или Neon.
2. Установите DATABASE_URL в окружении сервера по образцу .env.example. Сам файл .env.example содержит только шаблон.
3. Выполните команды:

```sh
npm run db:init
npm start
```

Инициализация создаёт 20 таблиц, связи, 25 индексов и шесть стартовых пользователей. Повторный запуск сохраняет существующие записи. schema.sql задаёт общую структуру; initialize-database.mjs применяет её к PostgreSQL и запускает seed.js. Для выполнения в SQL-консоли предоставлен database.sql с начальной схемой и тестовыми записями; он предназначен для пустой базы. Пересоздать экспорт можно командой npm run db:export.

В размещённом Worker DATABASE_URL задаётся в серверной конфигурации, BUCKET связывается с R2. Клиент получает результаты API.

## Проверка и сборка

```sh
npm test
npm run build
npm run validate
```

npm test выполняет app.test.mjs и regression.test.mjs: позитивные, негативные, критический путь и безопасность. Изолированные проверки используют SQLite. При заданной DATABASE_URL интеграционная проверка выполняет реальные операции с PostgreSQL:

```sh
npm run test:postgres
```

Она создаёт проверочные вакансии, отклики, планы и PDF в выбранной тестовой базе. Для повторения используйте отдельную базу с начальным набором. Протокол находится в TEST_PROTOCOL.md, результаты PostgreSQL — в POSTGRES_RESULTS.json, реестр ошибок — в BUG_REPORTS.md.

Сборка помещает самостоятельный Worker в dist/server/index.js. Секреты, зависимости, локальная база и вложения исключены через .gitignore.

## Публичный адрес

Вход к размещённому приложению предоставляет функция Neon `wittehrbisenkulova` на Node.js 24. Её обработчик — `public-route.mjs`; `APP_ORIGIN` задаётся в серверном окружении и содержит HTTPS origin приложения без завершающего слеша. Значения серверного окружения в репозиторий не включены. Функция сохраняет пути, параметры, прикладную сессию и бинарные документы, проверяет источник изменяющих запросов и ограничивает размер тела.

Проверка входного обработчика: `node --test public-route.test.mjs` (7 сценариев).
